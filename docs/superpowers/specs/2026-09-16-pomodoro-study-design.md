# 番茄专注桌面应用设计规格

- 日期：2026-09-16
- 状态：设计已确认
- 项目名：`pomodoro-study`
- 产品名（暂定）：番茄专注
- 目标平台：Windows 桌面

## 1. 背景与目标

本应用用于降低开始学习时的决策成本，并把每一个专注阶段绑定到明确的
学习任务。产品遵循经典番茄工作法，但不引入打卡压力、强制锁机或复杂
学习计划。

核心目标：

1. 用户始终知道当前正在完成哪项任务。
2. 开始专注只需要选择任务并点击一次。
3. 计时状态准确，切换到休息后视觉感受轻松、不刺激。
4. 任务与专注记录完全保存在本机，无需账号。
5. 用户能快速看到今天和最近 7 天的专注情况。

## 2. MVP 范围

### 2.1 任务管理

- 新建学习任务。
- 选择当前任务。
- 将任务标记为完成。
- 删除未完成或已完成的任务，并在删除前要求确认。
- 使用软删除：任务从活动列表移除，但历史专注记录保留。
- 当前正在计时的任务不能直接删除；用户必须先暂停并结束当前阶段。
- 查看任务累计专注分钟数和已完成番茄数。
- 未完成任务排在前面；已完成任务折叠在列表底部。

### 2.2 番茄计时

- 默认专注 25 分钟、短休息 5 分钟、长休息 15 分钟。
- 每完成 4 个专注番茄，下一次休息使用长休息。
- 开始专注前必须选择任务。
- 支持开始、暂停、继续和提前结束当前阶段。
- 阶段结束后通知用户，但由用户手动开始休息或下一轮。
- 只有完整完成的专注阶段才计为一个番茄。
- 提前结束的专注阶段可记录实际专注时长，但不增加完整番茄数。
- 中断、跳过休息和切换任务均不得造成错误累计。

### 2.3 今日与趋势

- 今日专注分钟。
- 今日完成番茄数。
- 今日完成任务数。
- 最近 7 天每日专注分钟趋势。
- 统计按本机本地日期分组，并正确处理跨午夜。

### 2.4 桌面集成

- 系统通知：阶段完成时发送通知。
- 系统托盘：关闭主窗口时隐藏到托盘，计时继续。
- 托盘菜单：显示/隐藏窗口、开始/暂停当前阶段、退出应用。
- 窗口置顶：可在主界面工具栏切换。
- 单实例运行：再次启动时唤回已有窗口，不创建第二个实例。

### 2.5 主题

- 提供浅色和深色主题。
- 主题按钮位于主界面右上角工具栏，排列为“主题、置顶、设置”。
- 点击主题按钮在浅色与深色之间立即切换。
- 主题选择写入本地设置，下次启动时恢复。
- 专注状态使用番茄红；短休息和长休息使用低饱和鼠尾草绿。
- 休息主题不替换专注语义色，只覆盖当前阶段的强调色。

### 2.6 明确不做

- 账号、云同步和多设备同步。
- 移动端。
- 社交、排行榜和学习小组。
- 日历、课程表、长期周计划。
- 强制锁机、屏蔽应用或惩罚机制。
- 复杂标签、分类和任务优先级系统。

## 3. 主界面设计

### 3.1 布局

默认窗口约为 `960 x 680`，采用双栏结构：

- 左侧任务栏宽度约 340 像素。
- 右侧为计时、统计和趋势工作区。
- 窗口缩小时优先压缩间距，窄窗口下任务栏移动到计时区上方。

### 3.2 左侧任务栏

- 标题“今日任务”和本地日期。
- 顶部添加任务输入框。
- 任务项显示标题、今日专注分钟和番茄进度点。
- 当前选中任务使用低强调背景高亮。
- 每个任务提供删除操作；点击后显示确认对话框。
- 已完成任务折叠显示在底部。

### 3.3 右侧计时区

- 顶部展示当前任务。
- 右上角工具栏依次为：主题、置顶、设置。
- 阶段标签显示“专注中”“短休息”或“长休息”。
- 环形倒计时显示剩余时间与当前阶段进度。
- 循环点显示当前 4 个番茄中的位置。
- 主按钮根据状态显示“开始专注”“暂停”“继续”“结束休息”。
- 次按钮根据状态显示“提前结束”或“稍后继续”。
- 无选中任务时，主按钮禁用并提示先选择任务。

### 3.4 统计区

- 三个并列指标：今日专注、完成番茄、完成任务。
- 下方展示最近 7 天专注分钟柱形趋势。
- 数值使用等宽数字，避免更新时跳动。

### 3.5 设置抽屉

设置页覆盖或从右侧滑出，不离开主任务上下文。包含：

- 专注时长。
- 短休息时长。
- 长休息时长。
- 长休息间隔。
- 通知声音开关。
- 默认主题。
- 窗口置顶。
- 恢复全部默认设置。

### 3.6 颜色

浅色主题：

- 番茄红：`#D84F3F`
- 柔和休息绿：`#4D7C68`
- 休息浅色背景：`#EEF5F1`

深色主题：

- 番茄红：`#FF6654`
- 休息强调绿：`#7EAE96`
- 休息操作按钮绿：`#4D7C68`
- 休息深色背景：`#20372F`

休息颜色必须保持低饱和，避免高亮青绿色造成视觉疲劳。文字、图标和
交互控件必须满足可读性要求，不依赖颜色单独表达状态。

### 3.7 界面状态

需要明确实现以下状态：

- 无任务。
- 已选择任务，等待开始。
- 专注进行中。
- 专注已暂停。
- 短休息或长休息。
- 阶段已完成。
- 数据保存失败。
- 数据文件损坏并已恢复。

## 4. 技术架构

### 4.1 技术栈

- Electron
- React
- TypeScript
- Vite
- Vitest
- Playwright
- electron-builder

选择 Electron 的原因：本机已有 Node.js 与 npm；Electron 适合实现托盘、
系统通知、窗口置顶和 Windows 安装包，并能使用统一的前端技术完成界面。

### 4.2 进程边界

主进程职责：

- 创建和管理窗口。
- 系统托盘。
- 系统通知。
- 本地数据文件读写。
- 窗口置顶与单实例控制。
- 应用退出与计时状态持久化。

预加载层职责：

- 通过 `contextBridge` 暴露最小的类型化 API。
- 不向渲染进程暴露 Node.js 或任意文件系统能力。

渲染进程职责：

- 展示任务、计时器、统计和设置。
- 运行纯 TypeScript 计时状态机。
- 通过预加载 API 请求持久化和桌面能力。

安全基线：

- `contextIsolation: true`
- `nodeIntegration: false`
- IPC 通道使用白名单。
- 所有输入在写入前验证。

### 4.3 代码边界

计划目录：

```text
src/
  main/
  preload/
  renderer/
  domain/
    timer/
    tasks/
    sessions/
    stats/
    settings/
  shared/
tests/
```

`domain` 不依赖 Electron，可在 Node 和浏览器测试环境中直接运行。

### 4.4 计时模型

计时器不使用每个 tick 递减秒数的实现。每个阶段记录：

- `startedAt`
- `durationSeconds`
- `pausedAt`
- `accumulatedPausedMs`

剩余时间通过当前时间与阶段开始时间计算，并对累计暂停时间进行扣除。
界面刷新只负责渲染，不负责定义剩余时长，因此休眠、系统卡顿或窗口隐藏
不会产生明显累计误差。

状态转换由纯 TypeScript 状态机控制：

```text
idle -> focus -> paused -> focus -> completed
completed -> shortBreak | longBreak -> idle
```

## 5. 数据设计

数据存放于 Electron `app.getPath("userData")` 目录下的 `data.json`。

```json
{
  "schemaVersion": 1,
  "settings": {
    "focusMinutes": 25,
    "shortBreakMinutes": 5,
    "longBreakMinutes": 15,
    "longBreakEvery": 4,
    "soundEnabled": true,
    "theme": "light",
    "alwaysOnTop": false
  },
  "tasks": [
    {
      "id": "uuid",
      "title": "复习线性代数",
      "createdAt": "2026-09-16T01:00:00.000Z",
      "completedAt": null,
      "deletedAt": null
    }
  ],
  "focusSessions": [
    {
      "id": "uuid",
      "taskId": "uuid",
      "startedAt": "2026-09-16T01:05:00.000Z",
      "endedAt": "2026-09-16T01:30:00.000Z",
      "focusedSeconds": 1500,
      "completed": true
    }
  ],
  "runtime": {
    "selectedTaskId": "uuid",
    "cyclePosition": 2,
    "phase": "idle",
    "deadlineAt": null,
    "pausedAt": null,
    "accumulatedPausedMs": 0
  }
}
```

写入策略：

1. 先写入同目录临时文件。
2. 使用原子替换覆盖 `data.json`。
3. 替换前保留最近一次有效备份。
4. 读取失败时尝试备份。
5. 主文件和备份均损坏时，重命名损坏文件并创建默认数据。

时间戳统一使用 ISO 8601 UTC 存储，统计时转换为本机日期。

## 6. 数据流

1. 渲染进程从主进程加载数据。
2. 用户选择任务并启动专注。
3. 计时状态机产生阶段事件。
4. 阶段完成或提前结束时生成专注记录。
5. 渲染进程请求主进程原子保存。
6. 统计模块从任务和专注记录派生今日数据与 7 天趋势。
7. 设置变更后立即保存，并同步主题、通知和置顶状态。

主进程不推导业务统计，避免业务规则分散。

软删除规则：

- 删除任务时只设置 `deletedAt`，不物理移除任务及其专注记录。
- 已删除任务不出现在活动列表和任务选择器中。
- 已删除任务的历史专注分钟仍计入今日统计和 7 天趋势。
- 如果删除的是当前选中但未计时的任务，清空当前选择。
- 如果任务正在计时，删除操作不可用，直到当前阶段结束或提前结束。

## 7. 错误处理

- 数据保存失败：保留当前内存状态，显示非阻塞错误，并在下一次状态变化
  时重试。
- 数据文件损坏：自动使用最近备份，并在界面中提示已恢复。
- 主文件和备份都损坏：保存损坏副本，以默认数据启动。
- 通知不可用：计时不受影响，界面内仍显示阶段完成状态。
- 托盘不可用：关闭按钮退回普通退出确认，避免用户误以为应用仍在运行。
- 时钟被修改：阶段性时间异常时重置当前阶段，不生成负时长或重复记录。
- 应用显式退出：保存当前运行状态；下次启动恢复未完成任务和循环位置。

## 8. 验收标准

1. 未选择任务时不能开始专注。
2. 完整完成 25 分钟专注后增加 1 个番茄和 25 分钟专注时长。
3. 提前结束不会增加完整番茄数，但会保存实际专注分钟。
4. 每完成 4 个番茄后自动将下一次休息设为长休息。
5. 关闭窗口后计时继续，托盘可恢复窗口。
6. 退出并重新启动后，任务、设置、主题和专注记录仍然存在。
7. 今日统计和最近 7 天趋势与专注记录一致。
8. 主题按钮位于置顶和设置按钮旁，切换后立即生效并持久化。
9. 短休息和长休息使用低饱和鼠尾草绿，浅色和深色主题下均清晰易读。
10. 删除任务需要二次确认，完成后任务从列表消失。
11. 删除任务不会删除其历史专注记录，今日统计和 7 天趋势保持不变。
12. 正在计时的任务不能被删除。
13. 数据损坏时应用仍可启动，用户能收到恢复提示。

## 9. 测试策略

单元测试：

- 计时器开始、暂停、继续、完成和跳过。
- 每 4 个番茄后的长休息逻辑。
- 提前结束与实际专注秒数。
- 今日统计、7 天趋势和跨午夜分组。
- 设置校验和主题持久化模型。
- 任务软删除、活动列表过滤和历史统计保留。
- 当前计时任务禁止删除。

集成测试：

- 原子保存、备份、恢复和损坏文件处理。
- IPC 白名单与参数校验。
- 应用重启后的数据恢复。

界面测试：

- 任务选择到开始专注的完整流程。
- 暂停、恢复、完成和休息切换。
- 删除任务确认流程与取消删除。
- 删除选中任务后清空选择，并验证历史统计不变化。
- 主题切换及暗色主题下的休息状态。
- 托盘隐藏与恢复。
- 无任务、保存失败和恢复提示状态。

界面测试应使用短测试时长，不能真实等待 25 分钟。
